# AL-FIRQA AN-NAJIYA — план развития платформы

## Текущее состояние

Репозиторий сохраняет React 18 + TypeScript + Vite + Tailwind и hash-навигацию, совместимую с GitHub Pages. В `main` перенесены 111 записей из текущего опубликованного каталога `gh-pages`; SoundHelix demo-источники удалены из React-данных. Главная страница, каталог, циклы, автор, библиотека, избранное, история, локальное сохранение позиции и мини-плеер продолжают работать локально в браузере.

Последний проверенный build: `npm run build` проходит через TypeScript и Vite без ошибок. Публикация React-сборки отправлена в `gh-pages` отдельным коммитом.

## Принципы реализации

- Не публиковать неподтверждённые аудиоисточники, тексты, аяты, хадисы, переводы или биографические сведения.
- Не показывать фиктивные счётчики: статистика строится из опубликованных сущностей.
- Автоматические AI-конспекты всегда иметь статус «Черновик — требует проверки» до редакционного подтверждения.
- Сохранять hash-навигацию до появления проверенного fallback для прямых URL GitHub Pages.
- Не помещать service-role key, Telegram token или другие секреты во frontend и `VITE_*`.
- Пользовательские данные изолировать RLS-политиками после подключения Supabase.

## Этапы

### 1. Контентный фундамент

Стабилизировать типы `Lecture`, `Cycle`, `Author`, `Book`, `Text`, `Transcript` и статусы публикации. Добавить поля происхождения, source URL, право публикации, редакционный статус и дату проверки. Отделить публичные fixtures от черновиков. Импортировать только подтверждённые записи из текущего архива.

### 2. Дизайн и библиотека

Продолжить premium editorial систему: единые токены цвета, типографика Inter/Amiri/Fraunces, спокойные разделители, адаптивная сетка, доступные focus-состояния и `prefers-reduced-motion`. Довести каталог, циклы, авторов, тематические подборки и единый поиск по опубликованным сущностям. Разделы книг, текстов, словаря и курсов показывать только после появления реальных материалов; до этого использовать честные пустые состояния с пояснением.

### 3. Аудиосистема

Сохранить и усилить текущий аудиоплеер: громкость, 0.5×–2×, seek, таймер сна, автопереход, позицию, историю и полноэкранный режим. При завершении урока автоматически запускать следующий урок текущего цикла; режим «Повтор урока» имеет приоритет, а после последнего урока цикл останавливается без перехода на первый. Сохранять текущий трек и точное время при смене видимости или уходе со страницы, восстанавливать seek после загрузки метаданных и не запускать аудио автоматически после перезагрузки. Нижний мини-плеер можно скрыть свайпом вниз и вернуть кнопкой со стрелкой; скрытие интерфейса не прерывает воспроизведение. Горизонтальный свайп влево переключает на следующий трек, вправо — на предыдущий; жест не перехватывается элементами управления. Следующим безопасным шагом добавить очередь, A–B repeat и временные закладки в localStorage. Офлайн-загрузка разрешённых аудио требует отдельной политики хранения и подтверждённых прав.

### 4. Конспекты и транскрипты

Создать схему структурированного конспекта: краткое содержание, цели, разделы, определения, термины, источники, выводы, вопросы и таймкоды. Транскрипты хранить абзацами с временными метками. До получения расшифровок не генерировать содержание лекций и не приписывать преподавателю неподтверждённые формулировки.

### 5. Книги и тексты

Добавить PDF-каталог, reader state, bookmarks, reading progress, тексты и переводы только после загрузки материалов с подтверждёнными правами распространения. Для каждой сущности предусмотреть источник, автора, редакционный статус и дату публикации.

### 6. Академия и словарь

После появления конспектов и текстов добавить courses → cycles → lessons → notes → quizzes. Ввести lesson completions, повторение и личные учебные цели без публичных рейтингов. Словарь строить из редакционно проверенных терминов с арабским написанием, огласовками, транслитерацией, переводом и связями с материалами.

### 7. Supabase backend

После получения project URL и publishable/anon key создать миграции для profiles, roles, authors, categories, courses, cycles, lectures, books, transcripts, transcript paragraphs, notes, bookmarks, progress, quizzes, notifications и audit logs. На всех пользовательских таблицах включить RLS. Публичное чтение ограничить опубликованным контентом; административные права проверять серверно через роли и Edge Functions.

### 8. Авторизация и личная библиотека

Добавить необязательную аутентификацию. До входа сохранять базовый прогресс локально; после входа — безопасно синхронизировать избранное, прогресс, заметки и закладки с конфликт-правилами. Не использовать `user_metadata` как источник административных прав.

### 9. PWA и офлайн

Добавить service worker, offline fallback и кэширование статических ресурсов. Приватные пользовательские данные не помещать в публичный cache. Офлайн-аудио и книги разрешать только для материалов, для которых подтверждены права и предусмотрено удаление локальной копии.

### 10. Admin и AI

Создать защищённый `/admin` только после backend/RLS. Редактор должен управлять публикацией, версиями, источниками и audit log. AI-функции ограничить черновиками: транскрипция/конспект/вопросы/словарь должны показывать использованные материалы, предупреждения о неполноте и требовать редакторского подтверждения.

### 11. QA и публикация

Проверить desktop, iPhone и iPad: открытие, поиск, play/pause, сохранение позиции, продолжение, hash-refresh, темную/светлую тему, keyboard navigation, reduced motion, ошибки медиа, manifest, sitemap и Pages. Публиковать только после green build и проверки главных пользовательских сценариев.

## Блокеры для следующих этапов

Для конспектов и транскриптов нужны полные расшифровки или разрешённый источник. Для книг и текстов нужны файлы и подтверждение прав распространения. Для синхронизации, профилей, заметок, админки и уведомлений нужен Supabase-проект и выбранная модель ролей. Без этих входных данных интерфейс может содержать только честные пустые состояния, но не выдуманный контент.
