# AL-FIRQA AN-NAJIYA — Maximum Evolution

## 1. Аудит исходного проекта (3 ноября 2026)

Проект продолжает существующий сайт, а не создаёт новый продукт с нуля. Репозиторий — React 18 + TypeScript + Vite + Tailwind SPA с hash-маршрутами, развёрнутый на GitHub Pages. Контент лекций и циклов хранится в TypeScript-файлах `src/data/`; `src/App.tsx` содержит маршрутизацию и большую часть экранов; `src/CollectionPages.tsx` — книги/курсы; `src/lib/` — auth и синхронизацию; SQL-миграции находятся в `supabase/migrations/`.

Подтверждённые действующие данные: 111 записей «Необходимые вопросы для каждого», 18 записей цикла «Три основы», сведения о книге и два ZIP полного цикла. Реализованы каталог с фильтрами и метаданными, включая фильтр цикла, избранное, история, локальная позиция аудио, плеер с Media Session, скоростью/таймером/повтором, закладки с заметками и тегами, TXT/PDF экспорт, локальные самотесты и личная библиотека. Добавлена версия JSON backup/restore для локальных данных. Service worker кэширует оболочку и ресурсы одного источника; он намеренно не кэширует стороннее аудио или приватные API-ответы. Есть светлая/тёмная темы, focus-visible и reduced motion.

Проверенные оставшиеся пробелы и риски: Supabase URL/key и production auth/RLS в этой рабочей копии не подтверждены; cloud adapters покрывают только часть данных. Нет структурированных конспектов/транскриптов, редакторской CMS и опубликованного Knowledge Center. Magic-link требует проверки callback в реальном владельческом backend. Поиск охватывает только существующие метаданные/описания и локальные заметки, не содержимое аудио; hash URL и текущий sitemap не обеспечивают полноценный SEO для SPA-экранов. Значимые изменения ниже прошли production build и ручные Playwright smoke tests, но автоматической CI тест-инфраструктуры и полной screen-reader/keyboard проверки ещё нет.

Это анализ исходников и настроек репозитория, а не подтверждение доступности production Supabase или юридических прав на каждый внешний файл. Существующие лекции, ссылки, функции, стили и содержимое должны сохраняться; изменения совместимы и добавочны.

## 1.1. Реализация и проверка текущего продолжения

- Исправлен прямой `#/lecture/<id>` вход: выбранная лекция и global audio source соответствуют URL; загрузка не начинает воспроизведение без действия пользователя.
- Подключён PWA manifest с GitHub Pages base path; `.gitignore` игнорирует локальные env-файлы и сохраняет отслеживаемый `.env.example`.
- Лекционные действия стали семантическими кнопками; подписаны seek ranges; auth dialog управляет фокусом и закрывается Escape.
- Порог desktop navigation поднят до `lg`: на планшете в портретной ориентации нет горизонтального overflow, отображается мобильная навигация.
- `public/manus-routes.json` синхронизирован с 13 существующими статическими/параметризованными hash routes; все 13 маршрутов проверены на iPad/iPhone viewport без горизонтального overflow и ошибок браузера.
- В Advanced Lecture Library добавлены фильтр по циклу, сброс условий и объявляемый счётчик; интерфейс честно показывает, что транскрипты пока не индексируются.
- Добавлена локальная версионированная JSON резервная копия: schema whitelist проверяет ID уроков, импорт объединяет данные без удаления совпадений, ограничен 5 MiB и не содержит аудиофайлов/credential-данных. Личные заметки в JSON не зашифрованы — UI предупреждает об этом.
- Проверено: `npm run build`, `git diff --check`, 13 hash-маршрутов при 768×1024 и 390×844 без browser errors/горизонтального overflow; direct lecture/audio mapping, 18-урочный фильтр и сброс до 129 результатов; backup export/restore merge и отказ от malformed JSON без изменений localStorage.

## 2. Принципы продукта и редакционная безопасность

Сохранить фирменное имя AL-FIRQA AN-NAJIYA, существующие знаки, структуру библиотеки и premium archive-позиционирование. Переходить к Old Money Minimalism и editorial typography постепенно: спокойная чёрно-белая основа, тонкие разделители, выразительная типографическая иерархия, свободное пространство, сдержанный собственный акцент. Уменьшать число повторяющихся плиток, избегать декоративной перегрузки, чрезмерных градиентов, золотых рамок, куполов и исламских орнаментов. Поддерживать светлую/тёмную темы, адаптацию iPhone/iPad/desktop, управление клавиатурой и `prefers-reduced-motion`.

Не сочинять религиозное содержание, аяты, хадисы, арабские оригиналы, переводы, источники или атрибуцию. Любой структурированный конспект, транскрипт, proof/quote и термин должен иметь происхождение, ссылку на источник, статус редакционной проверки и ответственное подтверждение перед публичной публикацией. AI, если будет добавлен позднее, производит только помеченный черновик, не публикацию.

Не публиковать пользовательские данные, сервисные ключи или непроверенные права на распространение. Публичный клиент Supabase может использовать только anon/publishable key и только при проверенном RLS; `service_role` никогда не попадает во frontend. Административные полномочия проверяются на сервере, а не только скрытием кнопок. Не удалять имеющиеся материалы при миграции схемы или интерфейса.

## 3. Архитектура и границы систем

- `src/App.tsx`: hash-навигация, глобальное состояние плеера, маршрутные оболочки и личная библиотека. По мере роста новые функции выносить в компонентные модули без переписывания работающего SPA.
- `src/CollectionPages.tsx`: существующие каталоги книг и курсов.
- `src/data/`: статические опубликованные лекции, циклы, книги, ZIP-ссылки и будущий редакционно проверенный поисковый индекс. Не помещать сюда непроверенные черновики.
- `src/lib/`: local-first repositories, валидаторы и адаптеры Supabase. Локальные функции сохраняют работу, когда облако не настроено.
- `supabase/migrations/`: аддитивные версии SQL-схемы, RLS и индексы. Новые пользовательские таблицы принадлежат `auth.uid()`; контент и роли имеют отдельные политики и серверные ограничения.
- `public/`: PWA manifest/service worker, статическая оболочка, robots, sitemap и корректные GH Pages ресурсы.
- `plan.md`, `TODO.md`, `README.md`: актуальные решения, outcome-критерии и инструкции без секретов.

Публичный клиент остаётся совместимым с GitHub Pages и hash URLs до тех пор, пока для более полного SEO не подготовлен проверенный статический prerender/fallback для каталога, книг, циклов и лекций. Внешние аудиозаписи и ZIP остаются внешними файлами; не копировать их в git или offline cache без подтверждённых прав и отдельного согласия по объёму хранения.

## 4. Поэтапная дорожная карта

### Этап 1 — надёжный и доступный фундамент (реализован, ручной smoke-test)

Синхронизация прямой lecture hash-ссылки с глобальным треком исправлена; web manifest подключён с GitHub Pages base path; `.env.local` исключён из git; карточки, плеерные ranges и auth dialog получили первые исправления доступности. Production build и ручные браузерные проверки пройдены на iPhone/iPad viewport; автоматизированный регрессионный test suite и полная screen-reader проверка остаются в работе. Аудиоматериалы и существующие user-data keys не менялись.

### Этап 2 — Advanced Lecture Library и безопасный full-text search

Фильтр по циклу, категории, автору, сортировка, сброс условий и понятный счётчик метаданных уже реализованы; поиск по фактическим аудиотранскриптам пока невозможен, так как проверенных текстов нет. Следом — связать поиск с будущими опубликованными конспектами/книгами и редакционными статусами, без выдуманных связей, затем уточнить SEO/prerender для GitHub Pages.

### Этап 3 — Audio Player, learning progress и личный кабинет

Сохранить текущий единый audio element, Media Session, позиции, bookmarks, повторы, скорость и сон. Разделить экранную логику на переиспользуемые компоненты, улучшить прогресс урока/цикла и сделать личную панель сводкой по уже имеющимся данным. Пока вход/синхронизация не настроены, пользователь видит локальный кабинет с ясным статусом устройства и экспортом; не обещать синхронизацию при выключенном backend.

### Этап 4 — конспекты, Knowledge Center и экзамены

Определить версионируемые модели Transcript, Note, Term, Citation и Quiz с `source_url`, происхождением/цитатой, редакционным статусом, проверившим редактором и датой изменения. Добавить представление конспекта с кратким содержанием, заголовками, терминами, доказательствами и связями только для реально подтверждённого материала. Построить тесты/экзамены с сохранением результата, повторной попыткой и связью с исходным уроком. Не генерировать и не публиковать доказательства или цитаты автоматически.

### Этап 5 — Islamic Book Library

Развить текущий PDF-каталог в reader/library интерфейс, прогресс чтения, библиотечные закладки и связи с аудиоциклом. Показывать оригинальный файл/перевод, автора, источник, права, редакционный статус и версию. Полные тексты/загрузки появляются только после поступления разрешённых файлов или официальных URL; существующая книга и связь с «Три основы» сохраняются.

### Этап 6 — Cross-device Synchronization и резервирование

Локальный versioned JSON backup/restore уже реализован: он schema-валидирован, ограничен 5 MiB, исключает аудио/credentials и объединяет импорт без удаления локальных записей; файл не зашифрован и UI об этом предупреждает. Для межустройственной cloud sync сначала подтвердить владельческий Supabase project, URL, anon key, redirect URLs, Auth email flow и staging; затем добавить миграции заметок/закладок/quiz attempts с RLS. Установить правила конфликтов, account-data export/deletion и протестировать RLS на нескольких пользователях. При неподтверждённой внешней среде продолжать local-first без обещания cloud sync.

### Этап 7 — PWA и offline

Подключить существующий manifest и корректный installability scope; обновлять кэш безопасно при выпуске новой версии. Кэшировать оболочку, опубликованные текстовые данные и явно разрешённые книги. Не сохранять в публичный cache личные данные, auth responses или стороннее аудио. Выборочные offline-аудио разрешать поштучно только при подтверждённых правах, понятном объёме и пользовательском контроле «скачать/удалить».

### Этап 8 — Admin CMS и публикационный workflow

Создать CMS только после настройки Supabase/backend и модели доверенных ролей. Использовать server-side/Edge Function checks, строгие схемы, draft → review → published transitions, версии, source provenance и неизменяемый audit log. Скрытая клиентская страница без серверной авторизации не считается CMS. Редакторские действия не должны изменять опубликованный контент до подтверждения.

### Этап 9 — международная доступность и эксплуатация

Добавлять международные языки только с проверенными переводами интерфейса и отдельными издательскими метаданными; арабский текст поддерживает корректный RTL. Проверять маршруты и ключевые сценарии на iPhone/iPad, клавиатуре, screen reader, zoom/reduced motion, offline/restore, прямом URL и медиа-ошибках. При наличии GitHub Actions добавить build/test/a11y gates до публикации.

## 5. Блокеры и внешние входные данные

Для cross-device sync, профилей, CMS и экзаменационных результатов необходим реально выбранный и настроенный Supabase project, безопасное хранение project URL/anon key, подтверждённые Auth callbacks и решение о ролях/сроках хранения/удалении. Для содержательных конспектов нужны расшифровки лекций или проверяемые официальные публикации и редактор, который подтвердит точность. Для текстов и offline downloads нужны файлы/официальные ссылки и подтверждённое право распространения. Эти зависимости влияют на этапы 4–8, но не блокируют улучшение локального приложения и его маршрутов.
